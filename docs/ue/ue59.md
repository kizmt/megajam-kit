# UE 5.9 (Preview) with the kit

The kit supports projects on UE 5.8.4 and on the UE 5.9 Preview side by side. Everything in `docs/ue/` was verified on
5.8.4; lines starting **5.9:** say what differs on 5.9 (from the 5.9 docs, offline in `docs/ue59/`). This note covers
the machine setup, switching a project, what 5.9 changes for the kit, and what is still to be confirmed on 5.9.

**Status:** Epic calls the 5.9 Preview "not fully quality-tested" (the 5.9 MegaJam Preview forum post). Which
engine a project uses is the director's call (CLAUDE.md "Engine version").

## Machine setup

- Install the 5.9 Preview from the Epic Games Launcher (Unreal Engine > Library > + > 5.9). It installs beside 5.8 in
  `C:\Program Files\Epic Games\UE_5.9`. The Launcher's install list may not show it yet; the kit's engine lookup
  falls back to that folder.
- **C++ needs MSVC 14.50 (found 2026-11-10 on the target PC):** 5.9's UnrealBuildTool bans the MSVC 14.51.x
  toolchains "due to compiler issues" and fails before compiling (`Result: Failed (OtherCompilationError)`, build log
  in `Saved\Logs\build-*.log`). VS 2026 18.10.3 ships only 14.51.36231. Fix: Visual Studio Installer > Modify >
  Individual components > **MSVC Build Tools v14.50 for x64/x86** (5.9 prefers 14.50.35717). It installs beside
  14.51; 5.8.4 builds with 14.51 today ("not a preferred version" warning) and should pick 14.50 once present.
- MCP setup is the same as on 5.8 (SETUP step 2: Unreal MCP + All Toolsets, Auto Start Server, Generate Client
  Config); the settings moved to Editor Preferences > Agentic Workflows > Model Context Protocol
  (`editor-scripting.md`).

## Switching a project

1. Commit (and push) the project. There is no way back in place: assets saved in 5.9 don't open in 5.8, so going
   back means checking out the commit from before the switch.
2. Close the editor. Right-click the `.uproject` > Switch Unreal Engine version > 5.9 (or set
   `"EngineAssociation": "5.9"`). On the target PC the 5.9 Preview isn't in the launcher's install list, so a project
   it creates gets a GUID (`{7FFA0ACD-461D-3AD7-8C43-49ACFDFEE0E8}`, registered under `HKCU\Software\Epic
   Games\Unreal Engine\Builds` as `C:/Program Files/Epic Games/UE_5.9`). The kit's scripts resolve it the same way.
3. `scripts\build.ps1` (it prints `engine: ...UE_5.9`): rebuilds the game module and any C++ project plugins for
   5.9. `Plugins\MegajamTools` is Python only (no modules): nothing to build; it registers from its `init_unreal.py`
   when the editor starts. Copy the kit's current `scripts\build.ps1` and `package.ps1` into the project
   first if the project's copies predate the engine lookup (they hard-coded `UE_5.8`).
4. Open the editor, let shaders compile, regenerate the MCP client config, check the Output Log for
   `Registering Toolset megajam_tools.toolsets.MegajamTools`, then rerun the kit checks on the project: a `camset.ps1` capture, `postkeys.ps1`, a `package.ps1` Development zip played from the zip.

## What 5.9 changes for the kit (details in the notes' **5.9:** lines)

- **Editor scripting** (`editor-scripting.md`): new Python/Blueprint libraries to create and edit Blueprints,
  graphs, nodes and variables, StateTrees, chooser tables and Dataflow graphs (no 5.9 page names the classes: grep
  the 5.9 Python stub); a built-in `execute_python` MCP tool; Python wraps Blueprint classes and user-defined structs
  as their own types (`BP_X_C`), so code comparing `type()` or type names needs `isinstance()` (or the cvars
  `Engine.Python.WrapBlueprintClassesOnDemand` / `WrapUserDefinedStructsOnDemand` restore 5.8 behaviour); the
  Python Foundation Packages plugin is removed (the kit doesn't use it); `load_level` gained an
  `UnsavedChangesPolicy` (default Fail).
- **MCP**: four meta-tools (`list_toolsets`, `describe_toolsets`, `describe_tools`, `call_tool`) instead of three
  (`gen/unreal/mcp.ts` handles both); a Toolset Registry chooses which toolsets agents may use; new toolsets (Console,
  Perf, Scene Capture, Blueprints, MVVM, Slate inspection, Texture Graph, widget animation, MCP Client, NavMesh);
  `ExitEditor`; per-call limit of about 120 s on Claude Code's side.
- **Rendering** (`lighting.md`, `materials.md`, `performance.md`): Lumen World Cache (opt-in, Hardware Ray Tracing
  only), AVBOIT order-independent translucency (Experimental), Ambient Lighting Volumes (Experimental, non-Lumen
  only), automatic Nanite culling improvements, shadow debugging views, Dynamic Wind for Nanite foliage
  (Experimental).
- **Animation** (`characters.md`, `animation-library.md`): IK Retargeter Proximity IK, Pelvis Volume and Limb Twist
  ops; Control Rig as an asset reference (older nodes deprecated); UAF additions and AnimGen.
- **AI and world** (`ai.md`, `worldbuilding.md`, `pcg.md`): StateTree scripting, progressive navmesh builds, World
  Partition and Data Layer Blueprint functions, PCG Concave Hull node and edge scripting.
- **Audio/UI** (`audio-ui.md`): subtitles embedded in localized Waves from 5.8 need migrating.

## To confirm on 5.9 (from the notes' audits)

Highest first: these decide whether the kit runs at all on a 5.9 project.
1. C++ build with MSVC 14.50 (`scripts\build.ps1`).
2. MCP: `gen/unreal/mcp.ts` against a 5.9 editor (meta-tools, `call_tool` shape, the required-argument quirks),
   skills loading, and `MegajamTools` registering with its access modes (`describe_toolsets` annotations:
   `get_sound_info` read-only) and its import tools working (they use `editor_toolset.toolsets.asset.import_asset`,
   which the 5.9 docs don't mention; if it moved, the two import tools say so and the rest still register).
   The kit's skills listed by `ListSkills` as `/Skills/MegajamTools/megajam-editor-scripting` and `.../megajam-assets`
   (check the key format and that `GetSkills` returns the text). The project Instructions from
   `agents/mcp-instructions.md`: the setting accepts the line, the `DefaultGame.ini` section and key it writes (record
   them here so a session can set it in the ini), and a reconnecting client receives it.
2b. Two Experimental features worth having by the jam, if they pass:
   - **PVE trees** (`worldbuilding.md` "Trees from PVE"): enable the plugin, `CreateGraph` from `DeciduousTree_01`,
     change a grower setting, `ExecuteGraph`, `Export` (Nanite Foliage and Static Mesh), place it, capture, and bench a
     stand of them (`performance.md` foliage bar).
   - **AnimGenOffline + Kimodo** (`animation-library.md` "Generated animation"): the director's one-time setup first
     (Hugging Face account with Llama 3 8B Instruct access, a read token in Editor Preferences > Plugins > Kimodo, the
     first Generate to download the weights). Then generate a 4 s walk and an action from text, bake to an Animation
     Sequence on a kit character, and check: VRAM and RAM with the editor open, time per clip, foot contact, retarget
     quality, and whether a script can set the prompt, generate and bake (only `AddGeneratedAnimationSectionAsync` is
     AI-callable).
3. The kit's test scripts on a 5.9 project: `camset.ps1`, `stability.ps1`, `postkeys.ps1`, `shots.ps1` (the `-game`
   Python capture scripts). A scan of `gen/` and the plugin (2026-11-10) found no code that compares Python types or
   type names (5.9 wraps Blueprint classes as their own types); code written from the notes' snippets may.
4. Asset pipeline: `gen/asset.ts` (Interchange FBX import), `gen/character.ts` and the retarget scripts.
5. `scripts\package.ps1` Development zip, played from the zip (firewall prompt, VC++ runtime).
6. Frame times: `camset.ps1 -Measure` at 4K against the 5.8 baseline on the same cameras.
