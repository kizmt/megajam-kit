# Procedural Content Generation Overview for UE

https://dev.epicgames.com/documentation/en-us/unreal-engine/procedural-content-generation-overview-for-unreal-engine?application_version=5.9

> An introduction to the Procedural Content Generation Framework and how it can be used in your Unreal Engine projects.

[image: Procedural Content Generation Overview for UE]

The **Procedural Content Generation Framework (PCG)** is a toolset for creating your own procedural content and tools inside Unreal Engine. PCG provides technical artists, designers, and programmers with the ability to build fast, iterative tools and content of any complexity, ranging from Asset utilities, such as buildings or biome generation, up to entire worlds.

[image: Advanced PCG Forest] Advanced PCG Forest

## Important Concepts and Terms

- **Points**: Locations in 3D space that are generated by the PCG graph and are often used to spawn meshes. Points contain information about their transforms, bounds, color, density, steepness, and seed. They can be assigned user-defined attributes.
- **Point Density**: A value stored on each point, usually from 0 to 1. When points are sampled, the density is the highest value of the density function inside the point's volume. Many nodes also use density as a weight, for example when filtering points against a threshold. In the debug view, density appears as a gradient on each point.
- **Splines and Areas**: An open spline describes a path; a closed outline can describe a filled area. Choose the form the next operation needs.
- **Datasets**: Groups of data. Ten points in one group are different from ten separate groups; some operations work once per group.
- **Attributes and Tags**: An attribute stores a value, such as height or distance. A tag labels a dataset so you can find it later.
- **Bounds**: The space data occupies. Bounds-based fitting and overlap checks are not exact mesh collision tests.

## Required Setup

The Procedural Content Generation Framework requires the **Procedural Content Generation Framework** plugin to be enabled in your project. For more information on enabling plugins, see Working with Plugins (-> working-with-plugins-in-unreal-engine).

The **Procedural Content Generation Framework Geometry Script Interop** plugin is required to sample points on Static Meshes.

## The Procedural Node Graph

The Procedural Node Graph is the central piece of the Procedural Content Generation Framework.

[image: PCG Graph Editor] PCG Graph Editor

Using a format similar to the Material Editor, spatial data flows into the graph from a PCG component in your level and is used to generate points. The points are filtered and modified through a series of nodes, with the output being updated in real time. The resulting points can be used to spawn a variety of assets.

### Create the PCG Graph Asset

To create a PCG Graph asset, follow the steps below:

- Right-click in the **Content Drawer** or **Content Browser**, navigate to **Procedural > PCG**, and select **PCG Graph**.
- Choose a name for the new asset and press **Enter**.
- In the **Create Graph From Template** window, select **Create empty graph** to start from a blank graph, or select a template and click **Initialize From Template**. The window appears only when at least one graph in the project is marked as a template.

### PCG Graph Templates

After creating a PCG graph, you can mark the graph as a template, which can then be selected from the context menu when creating new graphs. Similar to Niagara templates, you can expedite your workflow using a PCG graph template rather than starting from a blank graph.

#### Set a PCG Graph as a Template

To define a PCG graph as a template, open the graph and use the following steps:

- In the **Tool Bar**, click the **Graph Settings** button to populate the Details panel with the graph settings.
- Navigate to the **Asset Info** section of the Details panel and enable the Is **Template** property.

[image: Is Template Property] Is Template Property

Your graph is now defined as a Template Graph.

#### Creating a New Graph using a Template

When creating a new graph, after you choose the asset name and location, you can now select a ********graph template from the **Create Graph From Template** window. Select the graph template you want to use, then click **Initialize From Template** to create a new graph using the template.

[image: Select Template from Asset Selection Menu] Select Template from Asset Selection Menu

To disable the template prompt when creating new PCG Graphs, navigate in the menu bar to **Edit** > **Editor Preferences**. Then use the search bar or navigate to the **PCG Editor **section of properties and disable the **Show Template Picker** **on New Graph** property.

[image: Disable Template Prompt Property] Disable Template Prompt Property

When this property is disabled the **Create Graph From Template** window will not appear when creating new PCG Graphs.

### PCG Nodes

The PCG Graph is made of a series of PCG Nodes, each one performing an operation that contributes to the final result.

[image: PCG Node Palette] PCG Node Palette

These nodes are divided into the following categories:

| Category | Description |
| --- | --- |
| **Blueprint** | Contains Blueprint-related nodes. This includes the common node to execute user Blueprints derived from **PCGBlueprintElement**. To call editor-only Blueprint functions, such as **Editor Asset Library** or **Editor Level Library** functions, derive your Blueprint from PCG Editor Blueprint Element instead. This class is in the editor-only PCG Editor module, so you can only use these Blueprints in the editor. |
| **Control Flow** | Contains nodes for controlling the flow of logic through the graph. |
| **Data Layers** | Contains nodes that read World Partition Data Layers from actors and partition data by them. To assign Data Layers to spawned actors, use the Spawn Actor or Create Target Actor node. |
| **Debug** | Contains nodes that help with debugging. |
| **Density** | Contains nodes that affect point density. |
| **Dynamic Mesh** | Contains nodes that create and edit dynamic meshes. Requires the PCG Geometry Script Interop plugin. |
| **Filter** | Contains nodes that filter data based on criteria or per-point. |
| **Generic** | Contains nodes that affect data, but not spatial data. |
| **GPU** | Contains nodes that run on the GPU, such as Custom HLSL, Download From GPU, and Generate Landscape Textures. |
| **Graph Parameters** | Contains nodes that read graph parameters. |
| **Hierarchical Generation** | Contains nodes for controlling the Hierarchical Generation (-> using-pcg-generation-modes-in-unreal-engine) mode. |
| **Input Output** | Contains nodes that read and write external data, such as Alembic (-> alembic-file-importer-in-unreal-engine) files with the Load Alembic node (requires the PCG External Data Interop plugin). |
| **Metadata** | Contains nodes that interact with Attributes, whether on points or on Attribute Sets. |
| **Param** | Contains nodes that control retrieval of parameters from Actors or Blueprint variables. |
| **Point Ops** | Contains nodes that affect points and their properties. |
| **Reroute** | Contains reroute nodes for organizing connections in the graph. |
| **Resource** | Contains nodes that load and manage external resources. |
| **Sampler** | Contains nodes that generate points from a source of spatial data, such as volumes, surfaces, meshes, and navigation meshes. |
| **Spatial** | Contains nodes that create spatial relationships between data, change their internal spatial data, or retrieve data. |
| **Spawner** | Contains nodes that create new data or place Actors at given point locations. |
| **Subgraph** | Contains nodes that deal with using subgraphs. |

Skinned meshes are spawned with the **Instanced Skinned Mesh Spawner** node.

You can add **Comments** and **Reroute Nodes** to improve the readability of your graph.

### Attributes and Metadata

Attributes are similar to variables and store data defined by its name and type. There are two types of Attributes:

- **Static Attributes**: Attributes that are fixed and always present. These start with a `$`, such as `$Position`. `$Index` is also available, and `$NumElements` can be read from the Data domain as `@Data.$NumElements`.
- **Dynamic Attributes**: Attributes that are created at runtime, and stored as part of the **Metadata** of the graph data.

In the **Attribute Selector** menu, static attributes are listed under Properties and dynamic attributes under Attributes.

### Metadata Domains

When using Attributes in PCG Graphs, you must consider the Domain the Metadata exists in. The domain will control what kind of information you can save as well as how it can be used and manipulated later. For each metadata point must know which domain is supported, and which domain is the default. Domains are prefixed by @ when selecting them.

The attribute list view has a field to switch between domains.

 Domain Selection

There are two domains:

- The **Data** domain holds attributes that belong to the data as a whole, such as the transform of a spline. It can only have a single entry, and does not support multi-entries like the Elements domain. You work with it like any other domain; create attributes, or write to them with metadata operations, by prefixing the attribute name with `@Data`. For example, an attribute `MyAttr` in the Data domain is `@Data.MyAttr`. The Data domain is the default for spatial data that is not made of points, splines, or polygons.
- The** Elements** domain holds one value for each element. Its prefix depends on the type of data:`@Points` for point data.
- `@ControlPoints` for the control points of a spline.
- `@Vertices` for polygons.
- `@Elements` for attribute sets.

The Elements domain is the default for point data, attribute sets, polygons, and spline metadata.

If you don't specify a domain, PCG uses the default domain for that type of data.

### Attribute Selector

Some PCG graph nodes can be used to provide interoperability between static attributes and dynamic attributes through the Attribute Selector.

- Names starting with a `$` are static attributes, while names without are dynamic attributes.
- `@Last` represents the last dynamic attribute written to by the previous node.
- `@Source`, used in output selectors, means the same attribute as the input.

### C++ Settings Overrides

Some settings are marked as `PCG_Overridable` in the C++ property metadata. For Blueprint nodes, variables that are visible and instance editable are overridable.

To override a node manually, click the arrow at the bottom of the node to expose the advanced pins that are normally hidden. There are two types of pins:

- **Global override** (the Overrides pin): Accepts any number of attributes and overrides every setting whose name exactly matches an attribute name. If several settings share a name, use the full property path. Only the first attribute set connected to the pin and its first entry is used, unless the override is an array.
- **Single override**: Accepts any number of attributes and overrides the specific setting if an attribute is found with an exact match with the setting name, or any name if there is only one attribute. If nothing is connected to the single override pin, the Overrides pin is used.

Attribute types need to match but some types can be converted.

To know the exact name or type, use the tooltip on the override pin:

[image: PCG Settings Override] PCG Settings Override

 Since the domains are specific to each type of data, the C++ API of `UPCGData` has functions to find out which domains are supported, and to convert between `FPCGMetadataDomainID`, the internal class that specifies a metadata domain, and `FPCGAttributePropertySelector`, the exposed class that selects attributes and properties (`GetMetadataDomainIDFromSelector` and `SetDomainFromDomainID`). An attribute is identified by `FPCGAttributeIdentifier`, which pairs the attribute name with its domain. Each `FPCGMetadataDomain `has its own set of attributes and entries, independent from the others. `Accessors`use the `FPCGAttributePropertySelector` to reach the right domain.

#### Spline Metadata

On top of control point properties, you can add attributes to the control points of a spline. This metadata is interpolated when the spline is sampled, and behaves the same as point or attribute set metadata.

Similar to points, you can use **Add Attribute** to create a new attribute, or use the metadata operations and specify a given output target to write into this attribute.

In addition, metadata on control points is the default for spline metadata, but you can also be explicit with `@ControlPoints`.

## PCG Component

The procedural node graph can sample your level through the PCG component. This component holds an instance of your procedural node graph and manages the generation of procedural content.

The PCG component generates content both in the editor and at runtime. You can add it as a component to any actor, including Blueprint classes, or use it as part of the **PCG volume**, a basic volume useful for quickly setting up procedural content.

[image: PCG Volume for use with PCG Component] PCG Volume for use with PCG Component

To connect a PCG graph to your PCG component, follow the steps below:

- In the Editor viewport or **Outliner**, select the **PCG Volume** or **Blueprint Class** that you want to connect.
- In the **Details** panel, click the **PCG Component**.[image: PCG Conponent]
- Click the **Graph** dropdown and select the **PCG node graph** you want to use.[image: Adding the PCG Graph] Adding the PCG Grapht
- Click the **Generate** button to see your result.[image: Click the Generate button] Click the Generate button

The PCG component also controls how it generates. **Seed** changes the random result, and **Is Partitioned** controls how the generated content is stored. The **Generate**, **Cancel**, **Cleanup**, and **Clear PCG Link** buttons give you a way to manage the generated content directly; hold Ctrl and click **Generate** to force generation.

**Generation Trigger** sets whether the component generates on load, on demand, or at runtime, and **Editing Mode** controls whether generated content is saved. When Generation Trigger is set to **Generate At Runtime**, a **Refresh** button replaces the other buttons.

## World Partition Support

When PCG assets are assigned to a World Partition - Data Layer (-> world-partition---data-layers-in-unreal-engine) and an HLOD Layer (-> world-partition---hierarchical-level-of-detail-in-unreal-engine), the PCG graph generates the actors and assigns them to the same data layer and the same HLOD layer.

For more information about using PCG with World Partition, see Using PCG with World Partition (-> using-pcg-with-world-partition-in-unreal-engine).

## Create a Simple Forest Volume

A common use case for procedural generation tools is biome generation in an open world environment.

[image: PCG Forest Volume] PCG Forest Volume

To create a basic forest biome generator, follow the steps below.

This sample uses Materials and Static Meshes from the Megascans Trees: European Hornbeam collection downloaded using Fab.

### Create the Level

- Create a new Project (-> creating-a-new-project-in-unreal-engine) in Unreal Engine.
- Create a new Level (-> working-with-levels-in-unreal-engine) using the **Basic** level template. Save your Level.
- Delete the **Floor** Static Mesh and add a new Landscape (-> creating-landscapes-in-unreal-engine) to the level using Landscape mode.
- Using the Sculpt (-> landscape-sculpt-mode-in-unreal-engine) tools, add some variation to your Landscape.[image: PCG Level Landscape] PCG Level Landscape

### Create the PCG Volume

- Return to **Selection** Mode and enable the **Place Actors** window, if it's not currently visible.
- Use the **Search Classes** box to find the **PCG Volume** and add one to your level.[image: PCG New Volume] PCG New Volume
- Scale the PCG Volume to X=8.0, Y=8.0, Z=8.0

[image: PCG Scale Volume] PCG Scale Volume

### Create the PCG Graph Asset

- Right-click in the **Content Drawer** or **Content Browser**, navigate to **Procedural**, and select **PCG Graph**. If the **Create Graph From Template** window appears, select **Create empty graph**.
- Name the new asset **PCG_ForestGen** and press **Enter**.
- Double-click **PCG_ForestGen** to open the **PCG Graph Editor**.

### Connect the PCG Component

- In the Editor viewport or **Outliner**, select the **PCG Volume**.
- In the **Details** panel, click the **PCG Component**.
- Click the **Graph** dropdown and select **PCG_ForestGen** from the list.[image: PCG Connect Forest Graph] PCG Connect Forest Graph

### Create the Points

- In the PCG Graph Editor window, add a **Get Landscape Data** node to the graph.
- Drag from the output of Get Landscape Data and add a **Surface Sampler** node.[image: PCG Surface Sampler] PCG Surface Sampler
- Select the Surface Sampler and press the **D** key to toggle Debug Rendering.
- Back in the Editor window, select the PCG Volume and click the **Generate** button in the Details panel.

[image: PCG Points on the Landscape] PCG Points on the Landscape

You can now see the points being generated in the Editor viewport. The points conform to the shape of the Landscape.

### Add Variation

- In the PCG Graph Editor, select the Surface Sampler.
- Add more points by adjusting the **Points Per Square Meter**, **Points Extents**, and **Looseness** properties in the Details panel.Adjust the **Points Per Square Meter** to **0.15** to add more points to the space.
- The **Points Extends** property controls the size of each point's bounds. Change the **X**, **Y**, and **Z** values to **50**.
- The Looseness property determines how closely the generated points conform to a grid shape. Leave the **Looseness** value at **1.0**.[image: PCG Graph Points Adjustment] PCG Graph Points Adjustment

- Next, add a **Transform Points** node. This node adds additional movement, rotation, and scale changes to your points with a defined range. Connect the **Output** pin of the Surface Sampler node to the **Input** pin of the Transform Points node.[image: PCG Graph Transform Points] PCG Graph Transform Points
- Disable Debug Rendering on the Surface Sampler node and enable it on the Transform Points node.
- To add some rotation variation, change the **Z** value for the **Max Rotation** to **360**. This gives all the points a random rotation between 0 and 360 degrees.[image: PCG Graph Transform Rotation] PCG Graph Transform Rotation
- The PCG graph spawns points and rotates them to conform with the normal direction of the Landscape. Disable this extra rotation by selecting the checkbox for **Absolute Rotation**.
- To add some size variation set the **X**, **Y**, and **Z** **Scale Min** values to **0.5**. Change the **X**, **Y**, and **Z** **Scale Max** values to **1.2**.[image: PCG Graph Transform Rotation Settings] PCG Graph Transform Rotation Settings

The end result is a set of points with a good amount of variation.

[image: PCG Graph Transform Scale] PCG Graph Transform Scale

### Spawn the Static Meshes

- In the PCG Graph Editor, add a **Static Mesh Spawner** node to the graph viewport. Connect the **Output** pin of the Transform Points node to the **Input** pin of the Static Mesh Spawner.[image: PCG Graph Complete] PCG Graph Complete
- Select the Static Mesh Spawner.
- In the **Details** panel, locate the **Mesh Entries** option under **Mesh Selector Parameters**, and click the **+** button to add a Static Mesh to spawn.
- Click the down arrow next to **Mesh Entries** to open the array.
- Click the down arrow next to **Index [0]**.
- Click the down arrow next to **Descriptor**.
- Click the dropdown menu for **Static Mesh** and select the tree that you want to spawn. This example uses** SM_EuropeanHornbeam_Forest_01**.[image: PCG Graph Spawn Tree] PCG Graph Spawn Tree

You can add more Static Meshes and balance the variety using the **Weight** property of each mesh entry. The chance of an entry spawning is its weight divided by the total of all weights. For example, with weights of 3 and 1, the first mesh spawns about three times as often as the second.
